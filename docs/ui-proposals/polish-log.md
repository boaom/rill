## 0. 怎么"看"的（可复算，不是感觉）

| 手段 | 命令 | 看什么 |
| --- | --- | --- |
| 几何 | `node tools/probe.mjs <url> <png> W H --dsf=1 --report=r.json` | 每屏 `scrollHeight` / 横向溢出 / 内容底 vs 浮层顶 / 每个元素的字号 / 前景-背景对比度（含半透明层逐层合成） |
| 像素 | `python3 tools/analyze.py shots/candidates-1440x1100-full.png r.json` | 每格主色占比、平均明度、纹理量（相邻像素亮度差）、**两两颜色直方图 L1 距离** |
| 尺寸 | PNG IHDR 头直读 | 宽是否 = 目标宽（375 / 768 / 1440） |

三条"肉眼判据"被量化成阈值，用来替代看图：

1. **六格彼此看得出来不一样** → 两两直方图 L1 距离（0–200，越大越不像）：**最小 91.0**（C1↔C5，都是亮色密排），其余 ≥151。
2. **不留大片空白** → 每格"内容底 vs 浮层顶"（`contentBottom` 必须 ≤ `overlayTop`，否则内容被 tabbar / 输入条压住）；每格平均明度 + 主色占比，单色 >70% 视为"空"。
3. **文字能读** → 每个有文字的元素算 `fg/bg` 对比度，阈值 4.5（正文）/ 3.0（大字）；同时检查最小字号（正文 16 / 标签 12，playbook §10 红线）。

## 第 1 遍 · 最伤的三处（改了再截）

**① D3/C5 的搜索框提示字看不清**
- 位置：C5 屏顶 `搜一搜「雨后散步」`，12px，`#6A6A76` on `#E7E7EE` = **4.33:1** —— 六格里唯一的对比度不合格项。
- 为什么最伤：这是 D3 的第一眼动作（搜索 + 双列），提示字一虚，整屏就"发灰"。
- 改：`#6A6A76 → #5B5B67`。
- 改后：**5.34:1**（同屏最小值，达标）。

**② C4 的第三张卡宽图被 tabbar 切掉 43px**
- 位置：C4 第三卡（林见 / 晚霞）`16:9` 宽图；实测 `contentBottom = 797 > overlayTop = 754`。
- 为什么最伤：切口正好落在图片下缘，缩略图尺度下会被读成"这张图没加载完"。
- 改：宽图比 `16 / 9 → 21 / 9`（省 44px），并把卡间距统一到 9px。
- 改后：`contentBottom = 753 ≤ 754`，切割线落在卡片外边距上（不可见）。

**③ C2 与 C6 在缩略图尺度下像同一支**（这张"脸"的问题，眼睛会先看出来）
- 证据：C2/C6 的 4bit 颜色直方图 L1 距离只有 **34.9**（六格最小的一对），主色都是"暖纸底"（`#F0F0E8 84.3%` vs `#F0F0E0 77.1%`）。
- 为什么最伤：六格的任务是"一眼看出六种做法"；两格同色同温，评审会认为我们只做了五支。
- 改：C2 加**黑色表头条**（`#17130F`，白字）+ **黑色输入条**，纸底由 `#F7F3EA` 压到 `#F3EEE3` —— 正好落回 "墨黑 / 纸白 / 朱红" 三色纪律。
- 改后：**188.3**（从"最像的一对"变成"最不像的一对"之一）；黑块占 13.3%，色温和 C6 分开。

## 4. 各方向「真实内容下最可能塌的地方」（captain 指定）

| 方向 | 一句风险 |
| --- | --- |
| **D1 = C1（COLLINS）** | **高度预算**：62px 日期 + 转发嵌卡 + 九宫格三者同屏时，9 图只能露出 6 张；再接上「展开全文」（每多一行 28px）和第 3 条卡片，一屏就只剩 1.2 条。转发再转发（套娃）没有层数上限，需硬性规定**嵌卡只画一层**。 |

## 5. 只有人能下的结论（诚实声明）

1. **审美**：六格哪一格"好看"、C1 的黑白是否过于冷硬、C2 是否真的"用力过头"——这些没有阈值，我没有图像输入，没资格下结论。
2. **长文折叠 / 认证标识 / 客户端尾巴**：规则写了、DOM 位置定了，但**没有真实样本**可验；截图里看不到 ≠ 没设计。
3. **C1 的 6/9 张九宫格**是否会被误读成"只有 6 张图"，需要人看一眼。
4. `huashu-design/scripts/design_lint.py check` **跑不了**（它依赖 Python 版 playwright，本机没装，输出"体检跳过"），所以字号/对比度红线由本文件第 2 遍的 CDP 度量替代 —— 两者判据一致（正文 16 / 标签 12 / 4.5:1），但不是同一个工具。

# 第 3 轮 · 三个方向的完整初稿（t14）

> **设备框降级说明**：`huashu-design/assets/ios_frame.jsx` 是 React 组件（192 行，内含灵动岛 + 状态栏），纯 HTML 原型要么引 React + JSX 编译器（=外链 CDN，任务禁止），要么手绘灵动岛（任务明确禁止）。所以三张原型统一用**中性边框**（1px 描边 + 26px 圆角 + 外投影，不画刘海/状态栏），单屏出图模式（`?only=`）下连边框都不画，PNG 就是 375×812 的屏本身。

## 这组数据里有一条比"好看"更硬的结论

**B 的辨识度只在暗底成立。** 暗色下三支的深色像素是 53.3% / 50.8% / 48.5% —— 挤在一起；而亮色下 A/C 是 10.7% / 1.4%，B 换成亮色是 1.8%，几乎等于 C。也就是说：

- 用亮色为主场景 → **B 的身份消失**（零彩色近黑变成"浅底黑字"，与 C 的中性卡流难以区分），A 与 C 之间也存在同样的"浅底撞车"（直方图距离 52.9）。
- 用暗色为主场景 → **三支挤在一起**，A 靠"读数条/发布块反相成浅块"（10.5% 亮色像素）和 62px 日期仍能分层，B 只剩时间戳，C 只剩品牌红 1.06%。

结论给用户的话：**如果产品要同时支持亮/暗，B 需要为亮色另立一套版式，否则它在亮色下会退化成 C。** 这条不是设计偏好，是像素比。

# 第 8 轮 · t25：折叠态图片从「隐藏」改回「限量」

captain 的驳回成立：我把"140px 裁切"这个正确测量，推成了"折叠态不给图"这个错误规则。微博客户端的 feed 里**有图本身就是信息**，折叠态不给图等于让用户先点「展开全文」才知道有没有图——那是改产品语义，不是改版式。以下按"限量"重做，全部用实测决定档位。

## 改前（t22 版：折叠态 `display:none` 图格）

| 判据 | 改前实测 |
| --- | --- |
| `.feed` 裁切 | 0（靠不给图换来的） |
| 正文可见 | 6 行 168px ✓ |
| 折叠态可见图数 | **0 张**（这就是被驳回的点） |
| 卡高 | 251px（正文 + 按钮 + 计数） |

## 改后（t25 版：折叠态最多一行 3 张）

| 判据 | 改后实测 | 是否达标 |
| --- | --- | --- |
| `.feed` 裁切 | `scrollHeight 624 = clientHeight 624` → **0** | ✓ |
| 正文 6 行 | `clientHeight 168 = 6 × line-height 28`（**段落间隙在折叠态归零**，否则是 188 = 168 + 2×10） | ✓ |
| `展开全文` 命中区 | **64 × 44**，位于正文下 4px；`elementFromPoint` 取三点**全部命中 `.more` 自身** | ✓ |
| 折叠态可见图数 | **3 张**（一行，每格 111×111，图格高 111） | ✓ |
| 卡高 | 251 → **402px**；卡底 609 < feed 底 756，仍留 147px | ✓ |
| 展开态 | 9 张全量 3×3（335×335，`nShown = 9`） | ✓ |

**档位选择（用数字决定，不是观感）**：同样是 335px 内容宽，三种画法的图格高度实测为 —— **一行 3 张 111px** ／ **1 张 16:9 封面 188px** ／ **1 张 1:1 封面 335px**。3 张一行最省空间且信息量最大，所以**选 ≤3 张**，不降级到封面。若将来 375 以下更窄的屏（如 320）导致 3 张仍裁切，规则里的降级档写的是 **16:9 封面**（在两种封面里实测更省的那个）。

**短帖没被一刀切**：`?short=1` 用 32 字 + 9 图实测 —— 卡高 **521 < feed 624**，`nShown = 9`、裁切 0，**照常显示全部 9 图**。规则是"放不下时限量"，不是"一律只给 3 张"。

**一个被我自己拆掉的假阳性**：`overlap.expr.js` 报 `.para × .more` 重叠 3 处（ox 64、oy 24/20）。查下来是被 `overflow:hidden` 裁掉的那两段 `.para` 的**几何矩形**仍在，不是视觉遮挡；用 `elementFromPoint` 在 `.more` 的四角 + 中心取点，**三点全部命中 `.more` 本身**，判定为假阳性。
