## 3. 选择依据（三方证据，全部落盘）

1. **可读图视觉终审**（独立子代理，12 张全开）：A 第一、C 第二、B 第三。判词要点见 `polish-log.md` 的「视觉终审」一节。
2. **真实内容鲁棒性**（本项目已经踩过两次"设计稿看不出会不会塌"的坑，所以这一列权重最高）：A 是唯一原生支持九宫格 3×3 + 转发 quote rail + 真三栏 1440 的方向，结构冲突 **0**。
3. **迁移成本**（`A/tokens.md` §9）：42 个 token + 186 行组件 CSS，`spec.md` **零改动**（A 是唯一零结构冲突的方向）；B 需改 `timeline.js` 的滚动恢复，C 需改 `spec.md §4.2` 卡片结构表 + `--rill-title-clamp`。

## 4. 明确排除的理由（记录在案，避免以后翻案）

- **B 排除**：一屏一条在转发链、九宫格、长文展开三种形态上结构性崩塌（视觉终审判词："art project, not a shippable product"）；且其"零彩色近黑"识别度**依赖主题** —— 亮色下深色像素 1.8% ≈ C 的 1.4%，做双主题需为它另立一套版式。修完仍不改判（设计师可在充分知情下保留意见，但用户已选 A）。
- **C 排除**：双列瀑布在**转发卡**与**九宫格**两个最关键形态上坏掉；且被判定为"小红书衍生品、没有自己的声音"。
- 备选记录：若 A 落地后出现不可解问题，回退顺序为 **C → B**（C 的 token 变动最少，31 个）。

## 5. 批准后的约束（落地契约）

1. **A 方向为准**，B/C 的 HTML 与截图保留在 `docs/ui-proposals/` 作为决策档案，**不删除**（它们证明了"六个候选 → 三个方向 → 一个选择"的过程）。
2. **spec 变更清单**（A 落地时必须同步，由 captain 执行）：A 结构冲突为 0，因此 `spec.md` 主体不变；仅需新增三处——长文折叠（`展开全文`）、认证标识（黄 V）、客户端尾巴（`来自 xxx`）的字段与位置规则（详见 t21 引入的 `verified` / `source` 字段）。
3. **暗色**：A 在暗色下更分得开（亮色像素 10.5% 当锚点），双主题**直接支持**，不需要 B 那样的第二套版式。
4. **两条视觉终审指出的 A 缺陷必须在落地前修掉**：compose 屏 `发布` 按钮右侧的红色 `0.0`（bug，非风格）、375 读数条四数字挤一行、1440 读数重复、详情回复编号红色与动作强调色相撞。
