## 1. C1 · COLLINS：把"品牌即体验"落到界面的栅格纪律

- **选定逻辑**：最佳设计师 ①。理由：我们要的不是某个风格，而是"一个 App 能不能被认成有主张的产品"。COLLINS 的公开定位是把品牌当作可被走进去的体验来设计（站点自述），这套思维迁移到界面就是：**先定版式秩序，再谈颜色**。
- **已核实的事实**：`wearecollins.com` 可访问（HTTP 200，`<title>COLLINS</title>`）；站点自身的设计 token 就是纯黑白体系（`--color-black:#000` / `--color-white:#fff` / `--color-off-white:#f8f8f7` / `--color-off-black:#140700`）。**创始人姓名与履历未联网核实**，不作为论据。
- **借什么（只借 3 条规则，不模仿某件作品）**：
  1. **黑白为骨架，唯一强调色当"结构件"**——强调色只出现在"可操作"与"当前状态"，不出现在装饰上。
  2. **极端字号比**（巨标题 ↔ 小正文），层级只靠字号/字重/栅格，不靠投影与卡片。
  3. **严格栅格**：左右各留一条可复用的基线（我们把 375 宽切成 4 列栅格，卡片与详情共用同一套落点）。
- **一句话定位**：**像一本被认真排过版的日报，只是它能滑动。**
- **温度**：**大胆**（黑白骨架 + 极端字号比；六格里最用力的一支）
- **用在 Rill 的哪一屏最关键**：**时间线**。这一屏决定"这是不是被设计过"的第一眼印象；详情页沿用同一栅格即可，不需要第二套语言。
- **主角素材**：版面本身（巨字标题 + 严格的图文对齐）+ 数据即图像（计数行做成大号读数）。不依赖图片。
- **风险**：黑白+巨字在中文小屏上容易变成"海报压扁"。控制手段：正文严格 16px/1.75，巨字只允许出现在**单条地铁式分隔**（例如每 5 条之间一条"日期大标题"），不允许每条卡片都巨字。
- **与谁撞**：与 C3 同属黑白高对比色域 → 完整版必须拉开：C1 **严格栅格 + 一个强调色**，C3 **无可强调色 + 满版单图**。

## 2. C2 · Henry Steiner 石汉瑞：中文昵称 / 英文 handle 的"咬合"

- **选定逻辑**：最佳设计师 ②，一位东亚设计师，与 C1 的西方气质不同。理由：Rill 的题材事实里有一件事被所有方向忽略——**每条微博都是"中文昵称 + 英文 @handle"的混排**。这是最日常、也最没人认真处理的中文界面问题。
- **已核实的事实**：[Wikipedia](https://en.wikipedia.org/wiki/Henry_Steiner) 记载其身份设计作品包含 HSBC、Standard Chartered（渣打）、Hong Kong Jockey Club（香港马会）、Hongkong Land（置地）。具体版面规则**未核实**，以下是我们自己的归纳。
- **借什么（3 条）**：
  1. **双语不是"两套字体并排"，而是一次咬合**：中文与拉丁共用同一基线、同一光学字重（中文用 Noto Sans SC Medium ↔ 拉丁用同 x-height 的 Inter Medium），不出现"中文大、英文小"的默认落差。
  2. **三色纪律**：墨黑 + 纸白 + 一点朱红。朱红只给"转发/引用"这类**内容关系**，不给按钮。
  3. **引用块当"咬合"的展示窗**：转发原文用缩进 + 细线 + 字号降一档，把"谁在说谁"做成版面结构。
- **一句话定位**：**一条微博里两种语言，被排成一件对得上的东西。**
- **温度**：**大胆**（朱红三色 + 咬合排版，高对比、高信息密度）
- **用在 Rill 的哪一屏最关键**：**详情**（正文 + 转发链 + 评论者是三种不同层级的双语混排，这一屏最容易露怯）。
- **主角素材**：字形与版面（双语对齐规则）+ 数据即图像（楼层编号用小号数码）。
- **风险（也是它被排除的主因）**：这套逻辑搬到 App 界面极易退化成"海报感"——朱红三色与咬合排版需要留白空间，而 375 单列里没有。
- **与谁撞**：**与 C1 撞**（都是排版驱动、都靠对比而非色彩）。三方向里只能留一个。

## 3. C3 · BeReal："一天一次"的时间感，做成详情页的签名

- **选定逻辑**：现实参照 ①，同媒介（社交内容 App），且它解决的是和我们一样的问题：**怎么让"刷"这件事有节奏**。
- **已核实的事实**：[Wikipedia](https://en.wikipedia.org/wiki/BeReal) 记载其为 2020 年发布、主打真实的法国社交 App，其核心机制为"**once a day within two minutes**"（一天一次、两分钟窗口内发布），并被 Instagram/TikTok 以类似机制跟进。
- **借什么（3 条）**：
  1. **时间戳当主角**：不是灰色小字，而是"这条什么时候发生"的一行大字/大数字，在详情页占据一个明确的版面位置。
  2. **满版单屏**：一条内容占满一屏（一屏一条），滑动是"翻页"而不是"流水"。
  3. **极简两色**：黑与白，不加第三种颜色；不加装饰。
- **一句话定位**：**每条微博都像一个人此刻正站在你面前说话。**
- **温度**：**大胆**（满版单屏 + 时间戳巨字 + 无装饰，安静里的强反差）
- **用在 Rill 的哪一屏最关键**：**详情**。时间线的卡片形态不变，详情页被重做成"一屏一条 + 时间戳 + 无装饰"。
- **主角素材**：满版单图位（CSS 渐变占位 + 明确"照片位"标注）+ 时间戳巨字。**不引入位图**。
- **风险**：满版单屏会让 60 条评论的阅读变长（每翻一条要滑一次）。控制手段：评论区仍用紧凑列表，只让"正文 + 首图"满版。
- **与谁撞**：与 C1 同属黑白；与 C4 都偏暗（C4 暗的是"工具壳"，C3 暗的是"内容本身"）。

## 4. C4 · Ivory / Tweetbot（Tapbots）：微客户端的手艺

- **选定逻辑**：现实参照 ②，安静温度，用来回答"**同一件事别人做到了什么手感**"。Tapbots 是"微客户端"这个品类里被反复引用的手艺样本。
- **已核实的事实**：[tapbots.com/ivory](https://tapbots.com/ivory/) 自述"From the creators of the award-winning Tweetbot comes Ivory—a premier social media client for Mastodon"，并强调 "elegant design and whimsical iconography"；[Wikipedia](https://en.wikipedia.org/wiki/Tweetbot) 记载 Tweetbot 为 Tapbots 开发的第三方 Twitter 客户端（iPhone 2011 起），**已停服**。
- **借什么（3 条）**：
  1. **行内操作**：转发/评论/赞不跳页，在卡片底部就地展开，动效短（≤180ms）而确定。
  2. **自定义图标的"性格"**：图标要有统一的笔触与圆角逻辑（design.md 已有 9 个图标定义、实际挂载 7 个，stroke 1.75、24 网格 —— 这一步是打磨它们，不是重画）。
  3. **tabbar 是产品的"手"**：4 项等距、选中态明确、切换不闪屏。
- **一句话定位**：**同样的四条主线，别人做成了"用久了顺手"的那种质感。**
- **温度**：**安静**（深色工具壳 + 微动效；六格里最克制的一支）
- **用在 Rill 的哪一屏最关键**：**时间线**（行内操作 + tabbar 手感，是"刷"这个动作的全部摩擦力所在）。
- **主角素材**：图标与微动效（程序化）。
- **风险（= 被排除的主因）**：**与现有 design.md 基线同属"安静工具壳"家族**。它最可能的结局是"把现在的界面再擦亮一点"——差异落在温度与手感，而**不是版式结构**。directions.md 反复强调：三版要一眼看出差别；换皮不算方向。
- **与谁撞**：与基线撞；与 C3 都暗。

## 5. C5 · 中文内容瀑布流（App 风格库 #07，中性 92%）

- **选定逻辑**：秒数轮盘 ①。`date +%S` = 42 → `42 % 12 + 1 = 7` → App 分区第 7 号。
- **样张（已 `ls` 验证）**：`huashu-design/assets/style-specimens/app/07-feed-waterfall.jpg`（83,495 B）+ 同名 `.html` 源码（7,716 B）。
- **样张的视觉 DNA（skill 原文要点）**：白卡片 `#FFF` + 浅灰底 `#F5F5F7`；品牌红 `#FF2442` 只用于选中下划线、加号、关注、点赞态；中文无衬线，标题 15px 两行截断；**双列、列间距 6px、卡片圆角 10px**，封面比例 1:1~3:4 错落；卡片底部一行"头像 + 昵称 + 点赞数"。
- **借什么（3 条）**：① 错落的封面高度（同一批内容，视觉节奏靠比例差而非装饰）；② 两行标题 + 底部作者行（信息密度可预测）；③ 一点强调色只给"当前/已互动"。
- **一句话定位**：**最像中文内容产品的那一支：一眼就懂怎么用。**
- **温度**：**中性**（亮白双列卡流，没有强烈主张，也不刻意安静）
- **用在 Rill 的哪一屏最关键**：**时间线**（列数与封面比例是这一屏的全部）。
- **主角素材**：数据即图像（九图网格 + 封面比例）+ 程序化渐变占位。
- **风险 / 与 spec 的冲突（必须由 captain 裁决）**：spec §4.7 与 design.md 纪律 3 都假定**单列**信息流。C5 的双列会改掉结构 → **选它就必须允许改 spec 的"一屏预算"**。
  **降级路径**（不改 spec 也能借到一部分）：保持单列，但让封面比例在 1:1 / 4:5 / 16:9 之间变化，形成"单列里的错落"，并把底部作者行与点赞行的排布照搬。这样能拿到 70% 的观感而不动结构。
- **与谁撞**：与 C6 同属"中式亮色"（但 C5 是卡片流、C6 是色带导航，机制不同）。

## 6. C6 · 中国传统色·节气色谱（中文东亚 #07，中性 90%）

- **选定逻辑**：秒数轮盘 ②。同一个 `S=42` → `42 % 12 + 1 = 7` → 中文与东亚分区第 7 号。
- **样张（已 `ls` 验证）**：`huashu-design/assets/style-specimens/east/07-traditional-colors-solar-terms.jpg`（81,663 B）+ 同名 `.html`（6,097 B）。
- **样张的视觉 DNA（skill 原文要点）**：配色**用传统色名组织**（源：《中国传统色：故宫里的色彩美学》，384 色 + 24 节气色卡），24 条竖色条横贯底部，**当前那一条升高变宽并成为全页强调色**；暖纸底 + 墨色正文，纹样克制到几乎没有。skill 明确写：「**节气 = 导航** 是这个风格独有的版式动作」。
- **借什么（3 条）**：① 色条即导航，当前项升高变宽（一个动作同时表达"位置"与"当前"）；② 暖纸底 + 墨字的低刺激底色（长时间刷不累）；③ 用"名字"组织颜色，而不是用"红绿蓝"——我们的版本用日期/星期名，不用节气名。
- **一句话定位**：**把"时间"变成一条可以横着摸的色带。**
- **温度**：**中性**（暖纸底 + 低饱和色带，靠秩序而非对比取胜）
- **用在 Rill 的哪一屏最关键**：**我的**（我的微博按时间排列 → 时间轴色带最自然）或时间线顶部。
- **主角素材**：数据即图像（30 条 mock 的时间分布 → 24/7 条色带）。
- **风险（= 被排除的主因）**：**"节气 = 导航"是万能隐喻**——节气与微博内容毫无关系，硬搬会变成"设计在解释自己"。且 24 条竖色带与单列 feed 的结构不兼容（要么挤在底部 40px 里，要么改结构）。
- **与谁撞**：与 C5 同为中式亮色。

## 8. 收敛到 3 个方向的建议

### 建议保留：**C1（COLLINS）+ C3（BeReal）+ C5（瀑布流）**

| 方向 | 角色 | 一句话理由 |
| --- | --- | --- |
| **D1 = C1 COLLINS** | 最强 | 它是唯一"差别落在**版式结构**"的一支：栅格、字号比、黑白骨架——选它能一次性回答"这个 App 有没有设计主张"，而不是把现有界面擦亮。 |
| **D2 = C3 BeReal** | 最不一样 | 满版单屏 + 时间戳主角，把**详情页**做成产品签名；与 D1/D3 的骨架完全不同（翻页 vs 卡片 vs 栅格），且它带来的机制（"此刻"）能反哺时间线的节奏设计。 |
| **D3 = C5 瀑布流** | 最稳 | 六格里唯一"零学习成本、最像中文内容产品"的一支，适合作为产品经理视角的对照；**但要先裁决列数**（见下）。 |

**四条收敛理由逐条对上 skill 的要求**

1. **最强**：D1。它改变的是"怎么排"，不是"什么颜色"。
2. **彼此最不一样**：栅格排版（D1）↔ 满版翻页（D2）↔ 双列卡流（D3）。三者对"一屏放几条"的答案分别是"多条但秩序"、"一条"、"两列"。
3. **不撞同一外观家族**：D1 黑白+一强调色、D3 亮白彩色卡流 —— 天然分开；D1 与 D2 都在黑白域，用**"D1 有三个层级字号 + 一个强调色；D2 无强调色、一屏一条"** 硬性区分（写进方向卡，评审时按这条判）。
4. **最多一个用力过头**：只有 D1 的巨字算"用力"，但去掉巨字信息仍成立 → 属"用力"不属"过头"。真正会过头的 C2（海报感）与 C6（万能隐喻）已经排除。

### 需要 captain 先裁决的一件事

**C5/D3 是否允许改"单列"结构**（spec §4.7 + design.md 纪律 3）。
- 允许 → D3 就按双列做（差异最明显）。
- 不允许 → D3 降级为"单列 + 错落封面比例（1:1/4:5/16:9）+ 底部作者行"（观感约 70%，不动契约）；此时三方向仍成立，只是 D3 的"最不一样"程度下降。

## 9. 诚实声明（哪些是我们没看到的）

- **C1/C2/C3/C4 没有一张"界面截图"是我们的亲眼所见**。本机无 playwright（`ModuleNotFoundError`），本 runtime 模型不声明图像输入（`read_image` 直接拒绝），`web_search` 无 key。
  - C3 的取证物是 Wikipedia 条目页（[`_evidence/ref-bereal-wiki-1440.png`](_evidence/ref-bereal-wiki-1440.png)），不是 App 界面；
  - C4 的取证物是 Ivory 官网营销页（[`_evidence/ref-ivory-1440.png`](_evidence/ref-ivory-1440.png)），该页 99.8% 是近黑色 `#05050B`——只能证明"深色品牌基调"，**不能当界面参考**。
  - 因此 C1–C4 的全部"设计主张"都是**公开事实 + 我们的归纳**，不是对某件作品的观感描述。
- **两个库内样张我们截到了但看不到**：截图在 `_evidence/`，色板由脚本采样（§7 表格），视觉判断留给人。
- **第三备选未采用**：即刻（`web.okjike.com` 标题「即刻」，存在性已核实）——但与 C4 同属"中文社区客户端"，且其配色/结构我们未核实，不进六格。
- **未核实即不写**：COLLINS 的创始人履历、石汉瑞的具体版面规则、BeReal 的精确色值、Ivory 的实际界面元素，一律没有写成断言。
